Зачем понадобились эти дополнительные переменные?

--code-example-chrome-surface: var(--wa-color-surface-default);
--code-example-chrome-text-quiet: var(--wa-color-text-quiet);
--code-example-chrome-border: var(--wa-border-style) var(--wa-panel-border-width) var(--wa-color-neutral-border-quiet);

---

● Эти переменные нужны, чтобы ресайзер не перекрашивался вместе с превью.

  Почему без них ресайзер перекрашивается. .code-example-resizer лежит внутри .code-example-preview. Когда кнопка ставит на превью wa-dark или wa-light, тема Web Awesome переопределяет на этом элементе свои
  токены: --wa-color-surface-default, --wa-color-text-quiet, --wa-color-neutral-border-quiet и другие. Если ресайзер берёт var(--wa-color-surface-default) напрямую, он получает уже переопределённое значение. В
  итоге он перекрашивается вместе с превью, а остальная рамка примера (граница, панель кнопок, исходник) остаётся в схеме страницы.
  
  Как переменные это исправляют. Если в объявлении свойства есть var(), браузер подставляет значение на том элементе, где свойство объявлено. Потомкам достаётся уже готовый результат. Поэтому я объявил
  переменные на .code-example, то есть выше превью:
  
  .code-example {
    --code-example-chrome-surface: var(--wa-color-surface-default); /* подставляется здесь, в схеме страницы */
  }
  
  --code-example-chrome-surface получает цвет страницы. Ниже по дереву это значение не меняется, даже если на превью переопределены токены --wa-*. Ресайзер использует эти переменные, поэтому остаётся частью
  рамки. Это видно в первом прогоне в браузере: на тёмной странице со светлым превью фон превью стал rgb(255, 255, 255), а фон ресайзера остался rgb(16, 18, 25).
    
  Такой приём используется в CSS самого WA: там это --code-example-chrome-*.
  
  Можно ли без них. Да, есть два варианта:
  - Смириться с тем, что ресайзер перекрашивается вместе с превью. Тогда при переключенном превью его левая граница и фон будут выбиваться из рамки.
  - Вынести ресайзер из .code-example-preview в разметке CodeExamplePreview. Но тогда придётся переделать его позиционирование: сейчас он абсолютно позиционирован внутри превью и тянется по его высоте.
  
  Мне кажется, переменные проще и ближе к WA.

Хорошо. А почему в названии переменных есть слово chrome?

---

● Название взято из CSS примеров WA. «Chrome» здесь — термин из UI-дизайна, к браузеру отношения не имеет.

  Chrome — это обвязка интерфейса вокруг самого содержимого: рамки, панели, полосы прокрутки, кнопки управления окном. Отсюда и название браузера: у Google была идея свести такую обвязку к минимуму.

  В CodeExample содержимое — это превью с демонстрируемым компонентом. Всё вокруг него — обвязка: рамка, панель кнопок, блок с исходником и ресайзер. Префикс --code-example-chrome-* говорит, что переменные
  относятся к обвязке примера и всегда следуют схеме страницы, а не схеме превью.

  Если термин неочевиден, можно переименовать, например в --code-example-frame-*. Но с chrome проще сверяться с исходниками WA.
