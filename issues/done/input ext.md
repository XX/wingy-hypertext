Для компонента Input следует реализовать композитную структуру, чтобы переданные как children субкомпоненты могли заменить параметры label, text-field и hint. Структура должна быть похожа на устройство layout-компонента CodeExample: 
```
<Input hint="Input hint">
    <Label><div class = "custom">"Input label"</div></Label>
    <TextField placeholder="Enter your name" />
</Input>
```
Если в родительском компоненте Input указан параметр label или hint, то это значит, что их добавлять специально не нужно - скорее всего пользователь их укажет в children body или они должны отсутствовать. Если в Input children отсутствует и указан хотя бы один из параметров, относящийся к TextField, то TextField должен быть добавлен, иначе добавляются только сами children (в body которых пользователь может сам указать TextField). С параметром hint - по аналогии как у label.

Перед постановкой задачи проведено исследование наиболее приемлемой реализации поддержки слотов для пользовательского изменения структуры компонента: `rnd/component slots research.md`. В результате был выбран подход с передачей субкомпонентов в children.

  Что сделано

  Переработал Input в композитную структуру по образцу CodeExample. Теперь в crates/lib/src/components/input.rs четыре компонента:

  - Input — обёртка <div class="input …">, которая раскладывает дочерние элементы и/или достраивает части из shorthand-параметров.
  - Label — <label class="label"> с произвольным содержимым (generic R, children).
  - TextField — <div class="text-field"><input class="control" …></div> со своими параметрами (input_type, name, value, placeholder, disabled, readonly, required).
  - Hint — <small class="hint"> с произвольным содержимым.

  Логика композиции (как в задаче)

  Порядок вывода внутри обёртки: [Label?] → children → [TextField-авто?] → [Hint?], где:

  ┌──────────────────────────┬────────────────────────────────────────────────────────────────────────────────────────────┐
  │          Часть           │                                     Когда добавляется                                      │
  ├──────────────────────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ Label из параметра label │ если задан параметр label (даже при наличии children)                                      │
  ├──────────────────────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ Hint из параметра hint   │ если задан параметр hint (по аналогии с label)                                             │
  ├──────────────────────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ авто-TextField           │ только если children отсутствует и задан хотя бы один параметр поля (has_text_field_props) │
  ├──────────────────────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ children                 │ если переданы — целиком (там пользователь сам кладёт Label/TextField/Hint)                 │
  └──────────────────────────┴────────────────────────────────────────────────────────────────────────────────────────────┘

  Это в точности даёт пример из задачи: <Input hint="Input hint"> с <Label> и <TextField> в теле → label и поле берутся из body, а hint — из параметра. Покрыто тестом composite_children. Поскольку hypertext
  сплавляет children в один непрозрачный Lazy (это я проверял ранее), решение опирается только на то, что родителю доступно — children.is_some() и набор заданных параметров, без интроспекции детей.

  - CSS не трогал: суб-компоненты рендерят те же классы (.input, .label, .text-field, .control, .hint), поэтому существующие стили работают.

  placeholder, чтобы поле отображалось.
