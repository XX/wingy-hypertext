Нужно перенести компонент `Rating`, повторяя функционал `wa-rating` из WebAwesome: `tmp/webawesome/packages/webawesome/src/components/rating`. Это ряд символов (по умолчанию звёзд) для ввода или показа оценки. Место — `crates/lib/src/component/rating.rs`.

## Разметка

Пропы: `label`, `name`, `value`, `max` (5), `precision` (1), `readonly`, `disabled`, `required`. Значения по умолчанию как в WA.

Корень — `<div class="rating" role="slider" aria-valuenow aria-valuemin="0" aria-valuemax aria-label aria-readonly aria-disabled tabindex>`, внутри `max` элементов `.symbol`. Сервер полностью отрисовывает текущее значение: классы `symbol-active`, а для дробного значения частично закрашенный символ.

В WA `getSymbol` при каждом наведении заново генерирует HTML символов. У нас клиент разметку не генерирует, поэтому в каждом символе сразу лежат оба варианта (пустой и закрашенный), а показ переключается через CSS по `symbol-active`. Частичная закраска задаётся `clip-path` через CSS-переменную, которую выставляет клиент. Тогда при наведении WASM меняет только классы и переменную.

Символы по умолчанию — звёзды `regular`/`solid` из `iconic`. Свои символы передаются через подкомпоненты, а не через проп (как в `Drawer`/`Details`): например, `RatingSymbol` с `children` и, по желанию, отдельной разметкой для закрашенного состояния. Для Value-Based Icons нужен способ задать символ для каждой позиции. API продумать при реализации.

Значение для формы хранит вложенный визуально скрытый `<input>` с `name`. При значении 0 он пустой, поэтому `required` работает нативно. Свой текст ошибки и Custom Validity не переносим, как и в остальных компонентах формы.

## Поведение (`crates/web`)

- Клик выставляет значение с округлением вверх до `precision` по координате X. Клик по текущему значению сбрасывает его в 0.
- Наведение и перетаскивание (pointer events с `setPointerCapture`) показывают предварительное значение и увеличивают символ под курсором (`symbol-hover`).
- Клавиатура: стрелки меняют значение на `precision`, с Shift на 1; `Home` и `End` ставят 0 и `max`. Учитывать RTL.
- При изменении обновлять `aria-valuenow` и скрытый input, слать `change`. При наведении слать кастомное событие `wg-hover` с `phase` (`start`/`move`/`end`) и `value`; константа события — в `utils/event.rs`.
- При `reset` формы возвращать начальное значение.
- `readonly` и `disabled` отключают ввод.

Причина: Firefox тратит нажатие, закрывающее подсказку валидации, на её закрытие. До страницы доходит только `pointerup`, а `click` без нажатия не возникает, поэтому значение не выставлялось, а подсветка наведения сбрасывалась. Исправлено: значение выставляется на `pointerup`, обработчика `click` больше нет. Отпускание над рейтингом после нажатия вне его (например, в конце выделения текста) значение не меняет.
